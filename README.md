# THE LAST CHAPTER — Class of 2026

Event platform for the graduation night. Next.js (App Router) + TypeScript + Supabase.

**Status:** Uzbek student cabinet, persistent sessions, QR tickets, private photo/video memories, and admin panel.

## Run it

```bash
npm install
cp .env.example .env.local     # then fill in all five values
npm run dev                    # http://localhost:3000
npm run typecheck
```

### Supabase setup (once)

1. Create a project at supabase.com.
2. **SQL Editor**, run these files in order:
   1. `supabase/migrations/0001_foundation.sql`
   2. `supabase/migrations/0002_student_cabinet.sql` — personal codes, normalized lookup, pending tickets, private media bucket.
   3. `supabase/seed.sql` — creates the event. **Check the year in this file first.**
   4. `supabase/seed_test_students.sql` — optional, 4 fake students for testing.
3. **Project Settings → API**: copy the URL, anon key and service_role key into `.env.local`.
4. Generate `SESSION_SECRET` with `openssl rand -base64 48`.

`SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET` and `ADMIN_PASSWORD` are secrets: server only, never committed, never prefixed with `NEXT_PUBLIC_`.

Set `ADMIN_PASSWORD` to something long and random — this is the single shared password that unlocks `/admin`. Anyone who has it can see every student's data, so only give it to organizers you trust.

### Loading the real student list

Use `/admin/students` to add students or paste `First,Last,Class` rows. A fourth personal code is optional; omitted codes are generated by the database. Direct CSV imports can use `first_name,last_name,class_name`.

## How student login works

`/register` checks first name, last name and class against the organizer's approved list. Case, spacing, apostrophes and Cyrillic look-alike class letters are normalized. Unknown students cannot create accounts; ambiguous duplicate identities are refused.

This is name-based access, not strong proof of identity: someone who knows a classmate's full name and class may sign in as them. The personal code is an identifier shown after sign-in, not a password.

A valid sign-in sets a signed, httpOnly `lc_session` cookie for 45 days. Refreshing or reopening the browser keeps the session; explicit sign-out removes it. Every request verifies the student still exists and is registered.

A pending QR ticket is visible on the dashboard immediately. It becomes valid only when the organizer records confirmed paid contributions totaling the event minimum. A later sign-in never resets an existing ticket's status.

## Student pages (Phase 2)

- `/dashboard` — identity, personal code, QR/ticket number, countdown and all sections
- `/event` — schedule, what to expect
- `/movie` — vote once for the movie (only while the admin has voting open)
- `/music` — request a song, see your own requests' status
- `/memories` — write a memory or upload a photo/video up to 50 MB. Own submissions and approved gallery are available; `?type=image` and `?type=video` filter the page.
- `/ticket` — personal code, QR ticket, student name/class, ticket number and explicit pending/valid/used/revoked status.

## Admin panel

Go to `/admin` and enter `ADMIN_PASSWORD`. This is one shared password (not a Supabase Auth account per admin) — the
simplest thing that works for a small organizing team. Session lasts 12 hours.

- `/admin` — stats (students, registered, paid, not paid, entered, total contributions), movie vote bar chart, pending counts
- `/admin/students` — search/filter table, add one student, bulk-paste import (`First,Last,Class (optional fourth code)` per line), click into a student to edit, delete, or record a payment
- `/admin/students/[id]` — edit details, see their registration code, record a payment (activates a pending ticket when confirmed contributions reach the minimum), view their QR once they have a ticket
- `/admin/payments` — every payment record + total collected
- `/admin/movies` — add/edit/delete movie options (poster is a pasted image URL for now, not a file upload), open/close voting, see live vote counts, confirm the final movie
- `/admin/music` — approve/reject requests, filter by status
- `/admin/memories` — approve/reject/delete submitted memories, filter by status
- `/admin/settings` — toggle registration open/closed, edit event name/subtitle/location/date-time/minimum contribution

### What's simplified for now (by design, not forgotten)

- **Payment**: there's no live payment gateway yet (per the original spec — "do not fake payment confirmation"). The
  admin records payments manually on a student's page. Confirmed contributions reaching the minimum activate the pending ticket. Wiring
  a real Uzbekistan provider later means adding a webhook that calls the same "create a paid payment + ticket" logic.
- **Private media**: server-authorized uploads go directly to the private `memories` bucket. Pending/rejected files are visible only to their owner and admins; approved media is shared with signed-in students using expiring signed URLs.
- **QR check-in scanner** (`/admin/scanner`, camera-based entry): not built yet — this pass covered the panel itself.
- **Movie posters**: admin pastes an image URL rather than uploading a file (also a Storage feature, not built yet).
